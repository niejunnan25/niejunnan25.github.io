Event2Reward-Qwen3.5-4B-Stage1

Stage1 and Stage2 weights are public. The inference SDK and four LIBERO suite models are not yet public; SDK commands require code repository access.

Stage1 pretrained progress model and the initialization used for Stage2 joint training.

Model

Qwen3.5-4B with full BF16 parameters, a 101-bin progress head and a three-class auxiliary trend head. This checkpoint was saved at step 50,000 of the robot70_human30 run. The original learning-rate schedule was configured for 500,000 steps; this release is the 50,000-step checkpoint.

The bundle includes processor, tokenizer, configuration and training metadata. It does not include optimizer state or the full training datasets. Install the Event2Reward package from the source repository.

Use

from event2reward import Event2Reward, Observation
model = Event2Reward.from_pretrained("niejunnan25/Event2Reward-Qwen3.5-4B-Stage1")
obs = Observation("place the bowl on the plate", "start.png", "goal.png",
                  [f"h{i}.png" for i in range(5)])
print(model.predict([obs]))

For this Stage1 checkpoint, use five causal RGB history frames spaced 0.25 seconds apart, with the task text, episode start and an independent successful reference goal. Repeat the start frame for early history positions. The training recipe used goal dropout 0.5; the public example uses a goal-present input. Do not substitute a final frame from the evaluated episode for the independent goal. Downstream Stage2 and LIBERO examples use a different 0.1-second history interval.

The released loader always center-crops frames to 224 × 224. Stage1 training instead squared frames per source dataset (center crop, letterbox, or a fixed crop), so to match its training inputs, square non-square camera frames before passing them in.

Stage2 training can initialize from these parameters. See the adaptation guide. Reproducing training also requires the corresponding data and recipe; no exact optimizer-state resume is provided.

Results and limitations

No standalone policy success rate is assigned to Stage1. Progress is an uncalibrated learned estimate in [0,1] and may decrease or be inaccurate. Trend is an auxiliary training output. System-level LIBERO results belong to the full downstream method, not this checkpoint alone.
