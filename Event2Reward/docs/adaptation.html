Adaptation

Stage1 and Stage2 weights are public. The inference SDK and four LIBERO suite models are not yet public; SDK commands require code repository access.

Start from Stage2 (the jointly trained model) and provide successful, suboptimal, and failed trajectories for your own tasks. Install training dependencies first, including the additional Hopper requirements where applicable.

Dataset manifest

dataset.json uses event2reward.adaptation-data.v1:

{
  "schema": "event2reward.adaptation-data.v1",
  "dataset_roots": {"my_media": "media"},
  "train_sources": [
    {"path": "expert.jsonl", "index_format": "relation_v1", "role": "expert", "family": "expert", "clip_fraction": 0.5},
    {"path": "kind3.jsonl", "index_format": "relation_v1", "role": "event", "family": "event_kind3", "clip_fraction": 0.125},
    {"path": "kind4.jsonl", "index_format": "relation_v1", "role": "event", "family": "event_kind4", "clip_fraction": 0.125},
    {"path": "kind5.jsonl", "index_format": "relation_v1", "role": "event", "family": "event_kind5", "clip_fraction": 0.125},
    {"path": "kind6.jsonl", "index_format": "relation_v1", "role": "event", "family": "event_kind6", "clip_fraction": 0.125},
    {"path": "expert.jsonl", "index_format": "relation_v1", "role": "expert_fill", "family": "expert_fill", "clip_fraction": 0.0}
  ]
}

Paths resolve relative to the manifest. Each source must contain records; adjust source fractions for the event types you actually have. Fractions describe a clip budget, not equal numbers of relation groups. The fill source completes batches without breaking a relation group.

Prepare, inspect, train

Download Stage2 into checkpoints/stage2, then run:

event2reward-train prepare --recipe adapt --data-root data/my-task --dataset-manifest data/my-task/dataset.json --init-checkpoint checkpoints/stage2 --output-dir outputs/my-task --config-out configs/my-task.json
event2reward-train run --profile suite --config configs/my-task.json --check-only
event2reward-train run --profile suite --config configs/my-task.json

Preparation resolves paths, validates initialization and records the effective configuration. Check-only validates it before model loading. Re-run preparation into a new config filename after changing configuration, data, or implementation. Use --overrides overrides.json during preparation; never hand-edit a prepared config.

Supervision and optimization

The suite recipe uses a clip budget of 10 per device: half expert clips, with one eighth allocated to each of four event families, and expert filling for unused slots. Successful clips provide temporal progress and valid trend labels. Event clips use relation supervision (event_progress_objective=relation_only, hesitation_objective=relation); preserve progress_valid and trend_valid masks.

The default schedule is 500 steps with 25 warm-up steps, seed 42, accumulation 4, BF16 and SDPA. Learning rates are 2e-6 for language, 5e-7 for vision, and 1e-5 for prediction heads; the last three vision layers and merger are trainable. Loss weights are progress 1, trend 1, relation 10. Goal dropout is zero for suite adaptation. The complete recipe is distributed with the package.

Synthetic pipeline example

python -m event2reward.example_data --output data/synthetic
event2reward-train prepare --recipe adapt --data-root data/synthetic --dataset-manifest data/synthetic/dataset.json --init-checkpoint checkpoints/stage2 --output-dir outputs/synthetic --config-out configs/synthetic.json
event2reward-train run --profile suite --config configs/synthetic.json --check-only

The generator creates synthetic videos and all four relation types. Its labels are designed to exercise the pipeline, not to evaluate robot understanding. For a four-step smoke run, prepare with these overrides and then run normally:

{"stop_after_step": 4, "save_at_steps": [4, 500], "num_workers": 0,
  "gradient_accumulation_steps": 1, "keep_resume_states": 0, "log_steps": 1}

Keep the 500-step schedule and stop early; shortening the schedule changes the learning rates. Save optimizer state if you intend to resume training later.

Joint training

--recipe joint uses --profile joint. Full Stage2 retraining also requires the Stage1 checkpoint, pretraining replay, and source datasets; downloading Stage2 alone does not supply these. The released Stage2 parameters are from step 10,000 of a 40,000-step schedule. Do not change max_steps to 10,000 to reproduce that learning-rate trajectory. Joint replay uses source-specific goal dropout, unlike suite adaptation. The initial and resumed recipes preserve their execution settings.

The Stage1 initialization is niejunnan25/Event2Reward-Qwen3.5-4B-Stage1 (step 50,000). The jointly trained Stage2 checkpoint is niejunnan25/Event2Reward-Qwen3.5-4B-Stage2; the training recipe identifier remains joint. Stage1 uses a 0.25-second training history interval, while the downstream Stage2 and LIBERO recipes use 0.1 seconds. The Stage1 release provides parameters and metadata, not optimizer state for exact training resume.
