Rewards for robot reinforcement learning, learned from how progress
stalls, regresses, and recovers in real executions.

Abstract

Event2Reward learns task progress from successful demonstrations and the events in real robot executions. Temporal labels anchor the progress scale; local relations teach the model how progress changes through stalls, regressions, and recoveries.

Learning task progress from robot demonstrations provides a practical way to construct dense shaping rewards for robotic reinforcement learning. A common approach uses normalized demonstration time as progress labels, implicitly assuming monotonically increasing task progress. During policy exploration, however, actual task progress can stall or even regress. Such models may mistake regressions for progress, assigning positive shaping rewards to actions that cause progress loss. Real suboptimal and failed executions offer corrective experience, but assigning absolute progress values to their states is difficult. Our key observation is that stalls, regressions, and recoveries establish local relative progress relations even when absolute progress is unknown. We introduce Event2Reward, which uses normalized temporal labels to anchor the progress scale and these within-trajectory relations to constrain local changes, combining absolute and relative progress supervision. Its progress predictions serve as potentials for reward shaping. We curate an event-annotated dataset from approximately 100K raw real-robot execution records, covering successful, suboptimal, and failed executions, without requiring framewise absolute progress labels. Under the same training budgets, Event2Reward improves average policy success by 18.16 percentage points over a baseline using only sparse task rewards across 40 tasks in four LIBERO suites. On real robots, average success after 30 minutes of wall-clock training reaches 60.0% on three precise insertion tasks and 90.0% on three object manipulation tasks, exceeding the sparse-reward baseline under the same budget by 36.7 and 23.3 percentage points, respectively. Ablation studies further show that absolute progress supervision and relative progress relations are complementary, with joint supervision yielding better downstream policy learning.

Method

Progress written as inequalities between frames

Event2Reward does not need to know what fraction of a failed attempt is done. It only needs to know, for two moments, whether progress is higher, lower, or about the same.

Absolute supervision

In a successful execution, each frame is labelled with its normalized time, y_t = t / T: 0 at the start, 1 at completion. These labels set the progress scale.

Relative supervision

In an execution with an event, the annotation only marks where the event starts, a, and where it ends, r (a failed execution has no r; the interval runs to the end), and states how progress inside compares with a: about the same, lower, or not higher. No frame gets a number.

Read each kind of execution as an inequality

Pick a kind and an episode. Signs between stills: the relation the annotation requires. Numbers: Event2Reward’s prediction, which may differ. Click a still or drag the curve to move the video.

Blue curve: Event2Reward’s prediction. Black points a, r and the shading between them: the annotation. Hollow dots: frames sampled for comparison; red line or band: what the relation compares against. Held-out LIBERO test episodes, not used in training; videos play at 2×.

From inequalities to a reward

  1. Time labels set the scale. Successful executions are trained toward y_t with \mathcal{L}_{\text{progress}}.
  2. Inequalities set the direction. Each sampled frame in an interval is compared with its reference with \mathcal{L}_{\text{rel}}; a penalty applies only when the relation is broken.
  3. One model, one objective. \mathcal{L} = \lambda_p \mathcal{L}_{\text{progress}} + \lambda_{\text{rel}} \mathcal{L}_{\text{rel}} + \lambda_t \mathcal{L}_{\text{trend}}.
  4. Prediction becomes reward. r = r_{\text{env}} + \beta\,(\gamma\, p_{t+1} - p_t). Annotations are needed only for training; at reward time the model sees only camera images and the instruction.
